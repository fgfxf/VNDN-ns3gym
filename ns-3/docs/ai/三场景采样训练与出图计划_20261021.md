## 2. 为什么不能直接批跑现有脚本

| 已核实问题 | 本计划处理 |
|---|---|
| 旧训练 CSV 按 DATA/TIMEOUT 完成顺序写入“发送时六特征＋结果时服务站”，不是 hello 时间序列 | 新采样直接记录在线决策位置可见的10×6观测快照，不再把旧七列 CSV 连续滑窗作为正式输入 |
| 旧成功标签与约3秒 TIMEOUT 标签具有不同预测时域 | 统一用源 RSU 首次收到对应业务 Data 的时刻标注；即使车辆最终超时，也可有有效训练标签 |
| `run_experiment.py` 固定 `--save-data=0`，旧训练器也不识别新实验目录层次 | 增加独立训练快照开关及 manifest 数据入口，不靠开启旧 CSV 凑合衔接 |
| 当前移动日志缺加速度、方向、车道等在线特征 | 六特征来自 RSU 实际收到的 hello；移动日志只用于可追溯的未来关联标签及诊断 |
| 方阵现有两车只有同一底边路线；蜘蛛网低车数默认取前几条路线 | 在独立输入副本中增加合法且分层分配的路线族，实测七基站覆盖；不改路网几何或 RSU 位置 |
| 旧训练只有按目录排序的 train/validation，圆圈还能推断出非法类别 | 三场景统一显式分组划分、固定标签集合、独立模型评估集和哈希校验 |
| 目前只有单轮汇总，没有正式矩阵、跨轮统计和论文绘图工具 | 先补工具与测试，再冻结源码开始正式采样和实验 |

参考圆圈模型保留 TKAN-LSTM 结构和初始超参数，三个新模型从新数据重新训练。
旧 checkpoint、旧原始数据和 `ns-3_old` 只读保留，不覆盖。
旧100%验证准确率不作为本轮质量门槛；历史审计已发现其输入语义与在线过程不一致。

## 3. 先补数据契约，保持在线行为一致

### 3.1 输入：记录真实决策观测

在 RSU 收到符合现有神经决策条件的无线业务 Interest 时，旁路记录：

- `schema_version、scene、run_id、request_id、Name、vehicle_id、OBU node、source_rsu、decision_event_id`；
- 决策时刻（整数 ns）、候选 RSU 及顺序、原始请求与场景配置标识；
- 原始10×6数组，特征顺序保持 `x,y,speed,acceleration,angle,laneIndex`；
- hello 接收时间、实际历史长度、填充标记与历史年龄等审计信息。

抽出一个与在线 Gym 推理共用的观测构造函数，保证短历史左填充、无历史全零、
特征顺序及数值转换与当前在线实现一致。未来信息只能进入标签，不能进入观测或归一化。
一条新记录就是一个完整决策样本，不再对请求结果行做第二次滑窗。
记录按完整运行、车辆、源 RSU 和请求身份隔离，不能跨车辆/运行拼接历史。
空历史、短历史保留并分层报告；非有限观测明确拒绝并记录原因，不静默填造。

NoForward 的原生转发行为保持不变：旁路记录不连接 Gym、不改包、不改 PIT、
不改变事件执行顺序或消耗协议随机数。正式采样使用 NoForward。
样本身份包含`(run, request, OBU, source_rsu, decision_event)`，不能只按Name合并。
同一首次业务请求的生命周期内，每个源RSU只将第一次符合条件的无线决策观测纳入正式训练；
后续同源重复回调保留原始记录，标注其关联样本与排除原因，不再次增加训练权重。
不同源RSU各保留自己的首次观测、回程时刻和标签；合法多源接收不是身份歧义，
也不任取全网最先的RSU代替其他源。代理/非无线回调不进入样本集。
同一请求的多源样本保留关联分组，划分与不确定性分析不得将其当独立运行。
旁路去重状态与协议pending表分开，不为NoForward建立会影响转发的pending请求。
真正无法确认请求归属的记录保留诊断证据并拒绝自动标注。

### 3.2 标签：统一实际回程时刻

对每条已确认源 RSU 的样本，按完整 Name/车辆/请求身份关联：

1. 输出节点、Face及链路角色映射；从 `data-rx.csv` 找到该源RSU**从上级Router回程Face**
   首次接收对应业务Data的时刻`t_return`。排除无线收听副本、非回程Face和不属于本请求的包；
2. 从该 OBU 的 `mobility-events.csv` 恢复 `t_return` 时的服务 RSU；
3. 核验`request_send_time ≤ decision_time ≤ t_return ≤ request_deadline`，
   当前deadline为发送后3秒；不得跳过因果不符的首次包，再选一个较晚包凑标签；
4. 得到标签 `y=serving_rsu(t_return)`，并保存关联日志行、Face角色、时间及来源哈希。

| 情形 | 训练处理 | 论文性能统计 |
|---|---|---|
| RSU在截止期内有回程，车辆按时DATA | 标签有效时纳入 | 正常成功请求 |
| RSU在截止期内有回程，车辆TIMEOUT | 标签有效时仍可纳入，不能只训练成功请求 | 仍是失败，保留ISR分母 |
| 源RSU未观察到回程 | 标签未知，排除出有监督样本并报告 | 保留原请求及真实终态 |
| 首次回程晚于请求截止期 | 单列为late-return，仅作诊断，不用于正式监督训练 | 保留原终态，不把晚到包补成按时成功 |
| 回程时失联，服务站为-1 | 不扩充成新的输出类别，单独报告 | 保留失败/成功的真实记录 |
| 身份不清、非有限值、同纳秒关联顺序无法确认 | 明确无效原因，不推测补标签 | 不篡改原始事件与终态 |

圆圈输出固定 `0–1`，方阵和蜘蛛网固定 `0–6`。
按场景、参数、run、类别与终态报告生成数、可观察数、有效标签数、排除原因及比例，
防止只剩容易交付的训练样本却未披露选择偏差。
这个标签定义适用于本轮新 NoForward 数据，是实际回程目标的监督代理；
它不保证无线可达，也不等同于 Neural 选择其他路径后实际到达时刻的反事实真值。
正式在线评估仍记录真实选站、Data 回程和车辆交付，检查两者的差异。

## 6. 候选实验条件：预实验后冻结

起点沿用既有方案：`N₀=10`、速度设置`30km/h`、每车`5次/s`、
预热`t₀=20s`、请求窗`T=300s`、排空`3.5s`，因此`K₀=15000`。
预热与T需验证；T候选为200/300/600秒，优先三场景共用。
若T改变，按定义一致调整K；不会用不同仿真时长充当同一K扫描的不同水平。

| 扫描 | 五个候选水平 | 固定量 |
|---|---|---|
| 首次请求K | 3750、7500、15000、22500、30000 | N10、速度30、T300 |
| 速度设置km/h | 10、20、30、40、50 | N10、K15000、T300、路线族及请求时刻 |
| 车辆数N主扫描 | 5、10、20、30、40；K分别7500、15000、30000、45000、60000 | 每车5次/s、速度30、T300 |
| 固定K车辆数补充 | 5、10、20、30、40，均K15000 | 速度30、T300 |

速度只是设置值，附实际时间加权速度、分位数、停车比例及交接数。
圆圈原100m/s默认值不作为100km/h沿用。路网、RSU布置和无线条件不因算法而改变。
路线在测量和排空期间持续有效；车辆必须t₀前入场，不能用提前退出降低分母。
方阵新路线需真实到访七站，蜘蛛网按路线族分层分配车辆，避免N变化仅仅换了路线分布。
训练集、验证集和独立模型评估集各自需要类别覆盖；不要求每个单次运行恰好访问所有站。
如果某类在现有物理布局下无法观察，报告原因，不伪造类别、不擅自移动RSU。

### 6.1 预实验次序

先做三场景基准小规模冒烟与合法路线检查；没有新七类模型时，只用NoForward检查
采样/移动，测试控制器仅可验证接口，不评判模型性能。
再检查基准及三个主轴各两端的最多7种条件，初始每条件2个独立pilot种子：
`3场景×7条件×2种子=42轮NoForward`，作为首批预实验预算候选。
若某场景时长/入场/类别覆盖不合格，保留失败证据，在pilot域调整并重测。

有新候选模型后，用独立开发验证种子完成低/高负载的四策略工程预检，
测量神经控制器实际开销、完成率和日志规模；这些不进入论文正式测试。
预实验报告列出实际运行清单，不把42轮或历史252轮示例当作固定必跑充分性标准。
本轮已确定R=20，不根据正式曲线的优劣提前停止；若预实验表明其精度仍不足，
在开封正式测试之前报告并决定是否增加R，不称20轮必然充分。

## 7. 数据划分、种子与采样量

五个用途严格区分：pilot、train、validation、独立模型评估、最终四算法测试。
用master seed族分组，同族的车辆/请求及不同参数变体全部留在同一集合，
不随机拆重叠窗口，也不按目录“最后20%”划分。
每块保存ns-3 Seed/Run、SUMO、C srand、路线/请求生成及分析种子。
四算法共享同一块冻结输入；跨种子核验实际移动与请求是否确有变化，
不把同一轨迹换个目录名当独立重复。

建议预留互不重叠的用途编号域：
pilot `10000–19999`，train `20000–29999`，validation `30000–39999`，
模型评估 `40000–49999`，最终测试 `50000–59999`。
具体映射由manifest保存；这些是建议编号域，不表示每域所有整数都要运行。
同一道路/合法路线族可跨集合，完整车辆轨迹与随机实现不得复制跨集合；
本文主张新随机实现上的泛化，不自动声称未见路网或未见路线族泛化。

在候选17个正式条件上采样，先确保训练覆盖各单因素水平，
不额外承诺未训练的三因素组合泛化。一个可核算的采样预算候选为：

| 用途 | 每条件独立种子数 | 三场景×17条件的轮数 |
|---|---:|---:|
| train | 10 | 510 |
| validation | 3 | 153 |
| 独立模型评估 | 5 | 255 |
| 合计NoForward新数据 | 18 | 918 |

这张表是用于估时的候选，不是已确认的采样量；按Q4，P2后根据类别/交接覆盖、
样本相关性、CPU训练成本和有效记录量冻结，不能以原始记录数多替代独立变化。
原始数据全部保留。必要的训练抽样按参数、车辆、类别及交接状态预定义规则，
只用于train，保存确定性选样索引和权重；验证/评估/正式性能分母不这样缩减。
先计量完整数据训练开销，再决定是否抽样；不静默截取前几万个样本。
采用分块或内存映射读取，避免将全部10×6窗口同时堆入内存。

类别缺失、严重偏斜或交接样本不足在开发阶段按明确覆盖规则补采，
报告全部增补和排除量。训练、验证、测试均不能通过重新排列旧CSV伪造时序多样性。
模型冻结前允许对独立模型评估集执行预先规定的完整性、身份、标签支持数检查，
但不运行候选模型比较，不按预测表现增补或替换评估样本。覆盖不足时按事前规则
使用该用途预留种子补采并保留原数据；不得挑选“更好测”的种子。

## 8. 三个模型怎样训练与选择

| 项目 | 初始设置/约束 |
|---|---|
| 结构 | 沿圆圈 TKAN-LSTM，10×6，hidden32、KAN grid5、spline3、dropout0.1 |
| 输出 | 圆圈2类，方阵/蜘蛛网各7类，按明确RSU ID映射 |
| 优化 | train类别加权交叉熵、Adam、学习率0.001、batch256、最多100 epoch、patience15 |
| 初始化重复 | 每场景至少3个训练种子，共至少9次训练；与仿真种子分开 |
| 归一化 | 仅train拟合，推理复用同一参数与处理顺序 |
| 选模 | 仅validation；保存checkpoint、早停与跨初始化选模统一按macro-F1优先，再按未加权交叉熵较小排序；仍同分取较早epoch/较小初始化种子 |
| 转发阈值 | 保持现有0.10规则，正式测试不修改、不为了覆盖率强制总选两站 |

上述是初始候选配置，CPU吞吐与内存由预实验核实；batch等资源调整保持记录。
若需要结构/损失函数搜索，限定在开发数据和独立记录的候选预算中，
不得开封最终结果后继续追着测试集调模型。

类别权重沿用`w_c=N_train/(C×n_c)`，计数取最终选样后的train，保存计数与权重。
抽样后不叠加有放回类别均衡采样器或再套一份逆频率权重，避免重复补偿；
验证/评估指标按完整集合的原始频次计算。早停patience只在上述预定排序改善时重置，
数值同分容差在训练配置中预先固定。归一化、抽样与权重均不读取评估/测试统计量。
默认不做概率校准；若开发阶段增加校准，只能在validation上拟合并选择，
作为独立可追溯变更随模型一起冻结，不能看到独立评估结果后再校准。

每个场景输出checkpoint、训练/验证曲线、逐epoch日志、候选种子结果和选模理由。
冻结后在独立模型评估集报告：
top-1、macro-F1、balanced accuracy、逐类precision/recall/支持数、
当前单双路径规则的目标集合覆盖率、平均候选数、交接/非交接子集、
无历史/短历史及未知标签比例，并报告概率校准质量（不再拟合校准器）。
选站集合覆盖率必须同时报告复制成本，不用“总选两站”制造高准确率。
模型评估按完整run/seed族组织不确定性分析，不把相关窗口当独立样本。

模型权重、归一化、阈值及数据契约冻结后才计算独立评估预测指标并开始正式测试；
此前的完整性/类别支持审计不属于允许调参的性能反馈。
若结果不理想，保留并分析该版本；后续重新开发作为新版本，使用新的未见测试集。
本轮主实验固定一个被选中的模型，三初始化的离线结果不冒充20个仿真种子的模型稳健性证明。

## 9. 正式四算法配对实验：4080轮

算法统一为0 NoForward、1 VTDF、2 RTVTDF、3 新TKAN-LSTM。
每个场景使用自己的冻结模型，控制器逐轮重启，绝不用均匀测试控制器产生论文结果。

五水平的三个主扫描共享完全相同基准时，共`1+4+4+4=13`个唯一条件；
固定K车辆数补充扫描再加4个，合计每场景17个条件。

| 任务 | 计算 | 正式仿真轮数 |
|---|---|---:|
| 三个主扫描 | 3场景×13条件×4算法×20种子 | 3120 |
| 固定K车辆数补充 | 3场景×4新增条件×4算法×20种子 | 960 |
| 合计 | 3×17×4×20 | 4080 |

只有车辆、路线、请求、时窗、种子元组、模型及源码全部一致的基准块才可复用；
不能因为横坐标相同就复用不同随机实现。所有五项指标共用同批结果，不按每张图重复采样。
矩阵生成器只建立一个规范化基准条件ID，三项主扫描与固定K补图引用同一输入及结果，
不先各自生成不同基准输入，再按相近参数名合并。
若采用918轮采样候选，合计4998轮仿真，另加pilot/工程预检和至少9次模型训练。
采样总数与初步墙钟、磁盘成本在P2报告中明确；P4用冻结模型更新正式Neural估时，
不把候选轮数当成已执行量，也不把NoForward预实验成本冒充Neural成本。

矩阵调度器保存planned/running/complete/failed、attempt、退出码、完整配置和哈希。
恢复运行只跳过已验证完整且匹配冻结版本的块；失败尝试保留，按原输入重跑，
不得把重复同seed计作新增独立重复。批次异常先收敛本批进程，不影响用户其他进程。
协议TIMEOUT、低ISR、零成功是合法结果，保留；崩溃、提前退场或缺账本属于运行不完整。
正式汇总必须有全部预定比较块，不能静默做有利的完整样本子集。

## 11. 本机资源、估时与执行约束

核查时为10逻辑CPU、约9.5GiB内存、约927GiB可用盘；
PyTorch为CPU版本，CUDA不可用，不假设有GPU。
此前2车短运行的17.6–36秒/轮不能外推到300秒、40车或60000请求。

P2按场景、负载、车辆数分层测量单轮墙钟、峰值RSS、磁盘产物和训练/推理吞吐，
用各层实测成本乘冻结轮数加总，附失败重试余量和估算局限，不现在编造总小时数。
新模型工程预检后更新Neural运行估时；日志开关和产物策略保持冻结。
估时计入失败attempt、训练、采样和诊断留存；P2按实测单轮最大占用设磁盘余量门槛，
低于门槛时调度器停止启动新任务、保留已完成数据并报告，不自动删除原始样本。

所有waf及间接触发构建前`export JOBS=4`，显式构建`-j4`；
复用当前配置，不运行`./waf configure`。
SUMO/Gym仿真串行、训练任务串行，CPU线程有上限，不同时开多份重负载任务。
正式矩阵不用全量DEBUG或默认全程PCAP；结构化必需记录完整保留，
少数诊断种子另存PCAP并明确用途。
超时阈值依pilot实测预先设定，对同条件各算法一致；超时不能算成功或自动删除。
若数据规模大，优先分块读取与按计划分批，不偷偷减少测试种子或丢失不利条件。
