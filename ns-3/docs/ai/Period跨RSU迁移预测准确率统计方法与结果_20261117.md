# Period跨RSU迁移预测准确率：统计方法与20/40/80/160 ms结果

记录日期：2026-11-17。

本文件登记用户确认的“返回时跨RSU迁移预测准确率”口径，并用2026-10-26保存的20/40/80/160 ms记录复算。仅重新计数，没有重跑仿真、训练或模型推理；没有修改问题页、原图集或绘图脚本。

## 1. 指标定义

**指标名称：返回时跨RSU迁移请求的Top-1预测准确率。** 它衡量需要把Data送往其他RSU时，模型能否预测正确目标站，不代表全部请求准确率或兴趣满足率。

每条记录使用三个字段：

| 字段 | 含义 |
| --- | --- |
| `source_rsu_id` | 处理该请求并生成预测观测的源RSU |
| `label` | Data沿原路径从Router首次返回该源RSU时，车辆在协议关联日志中的服务RSU |
| `predicted_label` | 已保存的模型Top-1预测RSU，即对`probabilities`取argmax后按`probability_label_order`映射的标签 |

每一轮独立统计：

1. 读取该轮已有`predictions.jsonl`中的可评价记录，要求`exclusion_reason`为空。
2. 仅保留`label != source_rsu_id`的记录，形成返回时需要跨站的集合M。
3. 分母N为M的记录数；分子C为M中`predicted_label == label`的记录数。
4. 该轮准确率A＝100×C/N（%）。N为0时准确率未定义，应报告NA及样本数0，不写成0%或静默跳过。本次36轮的N均大于0。

同场景、同Period先分别计算三个种子的准确率，再取算术均值：

**表中Accuracy＝(A84001＋A84002＋A84003)÷3。**

保留全部三个种子；计算过程不提前四舍五入，最终显示两位小数。下方样本数表给出三个种子的C与N之和，供核对；均值Accuracy不是合并正确数除以合并样本数，两种汇总方式不能混用。逐种子计数见第5节。

筛选条件对四档完全相同，不按预测正确性、置信度或最终DATA/TIMEOUT结果选样本，不排除短历史。缺失标签的记录本身不进入有效预测文件，不能补成正确或错误。各档分别按自身真实标签筛选，**不取四档共同交集，也不要求四档真实标签相同**，因此各档分母可以不同。

与原handover子集的区别：原handover检查请求发送至3秒截止之间是否曾切换，可能包含回程之后才切换或切换后又回到源站的请求；本口径直接检查Router回程时`label != source_rsu_id`。

## 3. 准确率结果

每格为三个种子准确率的算术均值，单位为%。

| Period（ms） | 圆圈 | 方阵 | 蜘蛛网 |
| --- | ---: | ---: | ---: |
| 20 | 59.94% | 33.97% | 28.15% |
| 40 | 64.02% | 20.15% | 24.12% |
| 80 | 68.65% | 11.66% | 9.36% |
| 160 | 40.19% | 3.15% | 1.98% |

方阵和蜘蛛网四档逐步下降；圆圈20至80 ms上升，160 ms下降，不能写成三个场景都单调下降。

## 6. 解释范围

该口径针对迁移难例，起点可能明显低于总体准确率。它避免用大量“不迁移、预测源站即可正确”的样本掩盖问题；不能人为把数值调整到99%起步。

目前真实标签来自hello驱动的协议驻留记录，而不是独立于hello的物理最优基站。Period改变输入新鲜度，也改变关联过程与迁移样本组成；同时RSU超时按2T变化。因此，该表是现有协议和联动超时配置下的迁移条件准确率对照，支持分析相关性，不能单独证明hello改善预测或实际交付的因果关系。

迁移子集样本较少，尤其蜘蛛网每档三个种子合计仅87～116条；应连同样本数展示，不把末档两条预测正确扩大解释为所有请求的普遍表现。未进入可评价集合的请求与最终无线交付失败也不计入该指标，不能拿它替代兴趣满足率。
