# 旧脚本固定条数聚合与当前RTT图复算

日期：2026-11-17。本次修正前一轮把“画法”理解为外观的错误。只更新新问题页新增的六张图及脚本，上方原四张RTT图和原始数据保持。

使用与当前RTT相同的28轮逐请求记录、相同种子和[20,140)秒发送窗口。成功RTT仅选择DATA终态，平均RTT选择DATA和TIMEOUT终态，耗时均为terminal_ns-send_ns。来源路径及SHA256完整内嵌在六脚本的PROVENANCE，不从24个既有5秒均值展开伪造原始样本。

旧聚合的核心是`groupby(index // N).mean()`：圆圈N=20，方阵和蜘蛛网N=40；对发送时刻和RTT同时求算术平均，最后不足N条的组也保留。圆圈同原脚本在聚合后保留均值RTT<3000ms的组，本次没有组因此被删除。成功记录在分组之前按真实终态选择，保持“成功RTT”的定义。

当前逐请求事件不同于旧无表头CSV，输入次序明确如下：Circle/Grid按发送时刻、节点ID、请求序号生成一个流；Spider按来源种子升序，每个种子内按节点ID、发送时刻、序号拼接车辆记录，随后每40条聚合，最后按组平均发送时刻排序。这对应旧Spider“拼接车辆文件→分组→排序”的结构，跨车辆/种子边界的组保留，不把排序后的曲线称作固定时间窗口。当前车辆数、种子数与旧实验不相同，不能称逐样本复现旧实验。

每个均值组同权绘图。Spider保留五个种子的全部记录，未再次平均不同时间的聚合点；同一时段可能有多个点。该处理反映固定条数聚合，不能保证比5秒分箱更平滑。

外观采用原01/03脚本的策略顺序、配色、填充标记、线型、字体、线宽、图例及27°/-58°视角，单场景独立画布，保留真实z轴数值。未使用上一轮旧空心标记/25°视角。
