## Spider：多数请求没有进入回程阶段

核查 1500/12000 两档、四策略、两个种子，共 16 轮。下表为 TKAN-PDF 两个种子的计数之和，因此分母分别为 3000 和 24000。

| 观察阶段（唯一请求） | 1500 档 | 12000 档 |
|---|---:|---:|
| OBU Interest 出站 | 3000 | 24000 |
| RSU 上行 Interest 出站 | 1699 | 13583 |
| 服务器 Data 出站、RSU 完整接收、RSU 无线提交 | 1699 | 13583 |
| 目标 OBU 完整接收且按期满足 | 1690 | 13435 |
| 全部失败 | 1310 | 10565 |
| 其中未观察到 RSU 上行 Interest 的失败 | 1301（99.31%） | 10417（98.60%） |

“RSU 上行 Interest 出站”是请求被基站继续转发的代理证据，不能反过来断言缺少该记录就一定没有任何 RSU 收到无线信号。旧采集没有业务 Interest 的 RSU 入站轨迹。

四策略进入 RSU 上行阶段的比例都约为 56.5%–56.6%。同一条轨迹上多发请求，会同时增加可达时段成功的请求和不可达时段失败的请求，所以比值可接近不变。低负载到高负载，TKAN-PDF 原网络负载均值约从 250.32 增至 1764.66 Mbit，确实有流量增长。

### 覆盖证据及对“旧关联”假设的修正

依照保存位置、发射功率、接收灵敏度和传播模型，复算“至少一个 RSU 在理想无干扰情况下达到接收灵敏度”的车辆时间样本比例：

| 场景 | 第一个种子 | 第二个种子 | 均值 |
|---|---:|---:|---:|
| Grid | 93.3500% | 94.1917% | 93.7708% |
| Spider | 60.6417% | 52.6250% | 56.6333% |

每轮测量窗口包含 12000 个位置样本（10 车，每车 1200 个），同种子的四策略和五负载覆盖比例完全一致。这是 0.1 秒位置采样的必要条件，**不是 ISR 的严格上界**：它没有在每个发包瞬间重建信道，不能替代干扰、队列、车辆移动和协议状态。

尤其是 Spider `seed23018 / exp-00001`：测量窗口内距最近 RSU 的水平距离为 74.811–106.731 m，而配置推导的水平灵敏度半径约 63.077 m。1200 个样本全部位于所有 RSU 的这一范围之外。该车虽然持续记录旧 RSU5，低/高负载下各策略也确实全失败，但没有另一个理论可达 RSU 可以选择。

因此，**修正早期“旧关联可能是 Spider 大量失败主因”的猜测**：现有更强证据首先指向无线盲区。Spider 中“当前 RSU 不满足灵敏度、但另有 RSU 满足”的位置样本每轮最多 26/12000（0.217%），不足以单独解释约 44% 的整体损失。

共享 OBU 确有新鲜度缺口：`contrib/vndn-nn-rd/apps/vndn-obu.cc` 的 `OnSyncSignalInterest` 只在新 hello 到来时清除过期邻居；`SendPlannedPacket` 使用旧关联 MAC 前不检查 `lastUpdateMs`。邻居期限在头文件中为 2000 ms。若不再收到 hello，旧关联可继续被使用。

但原 `packet-l3.csv` 不记录 hello 入站，非驻留站 hello 也可能只更新邻居而不回复 Data。不能把“没有 OBU hello Data 出站”直接写成“没有收到 hello”。真实关联新鲜度需要增加接收时间和选站记录后验证。

### 无线建模需要单独审视

Grid/Spider 发射功率分别为 12/13 dBm，接收灵敏度均为 -69.8 dBm；Circle 为 10 dBm/-78 dBm。共同的 `WifiSetupHelper` 使用 `TwoRayGround`，传播频率默认 5.15 GHz，`MinDistance=50m`。当前传播实现对距离不超过 50 m 直接返回发射功率，形成明显功率平台；不能把源码中“约 300m”的注释当作实际覆盖。

来源见 `association/源码与覆盖核查.md`。两场景入口和 settings 等五个文件已与封存源码比对；四个未包含在旧封存 tar 中的依赖已与运行 manifest 记录的两个 Git 版本比对，内容一致。这是配置与源码重建证据，不冒充对历史二进制内部状态的验证。

## Circle：排序反转发生在无线提交后的交付

核查 9000/12000 两档、VTDF/TKAN-PDF、两个种子，共 8 轮、84000 个请求。表中计数为两个种子合计，分母分别为 18000 和 24000。

| 请求数/轮 | 策略 | Data 已回到 RSU | 3 秒期限前有无线 Data 提交 | 按期成功 | ISR |
|---:|---|---:|---:|---:|---:|
| 9000 | VTDF | 17669 | 11021 | 10244 | 56.91% |
| 9000 | TKAN-PDF | 17697 | 17697 | 11466 | 63.70% |
| 12000 | VTDF | 23249 | 13103 | 11540 | 48.08% |
| 12000 | TKAN-PDF | 23477 | 23477 | 9931 | 41.38% |

9000→12000 时，在已提交无线 Data 的请求中，TKAN-PDF 按期成功比例从 64.79% 降至 42.30%，VTDF 从 92.95% 降至 88.07%。TKAN-PDF 返回 RSU 的 Data 全部有期限前无线提交；VTDF 分别有 6648、10146 个返回请求没有期限前无线提交。

在 20–140 秒窗口内，12000 档每轮无线业务 Data L3 提交字节均值，TKAN-PDF 约 122.08 MB、VTDF 约 68.82 MB（十进制 MB）。统计仅选无线节点及无线 face，已排除服务器和 Router 上碰巧同编号的 face257。**全网总负载更低，不代表无线业务 Data 的负担也更低。** 此处是定位使用的局部计数，不替换 F03 原全网定义；L3 提交量也不等于 MAC 空口实际发送量。

成功请求从最后一次无线 L3 提交到应用交付的均值：12000 档 TKAN-PDF 两种子约 470/473 ms，VTDF 约 224/239 ms。仅比较两策略都成功的相同请求，差别仍存在：约 468/472 ms 对 205/232 ms；反而 TKAN-PDF 无线提交前约快 8 ms。因此本次 Circle 差别不能完全归于成功样本选择不同。

目前可确认的是末段交付位置和负担差别。排队、信道竞争、重试、分片/重组、目标站与车辆位置都可能介入；缺少 MAC 逐包事件，不能把“拥塞”写成已经完成消融验证的唯一根因，也不能只归咎于神经模型分类错误。

### VTDF 过期转发没有把 F01 抬高

四轮 VTDF 的过期额外提交数分别为 1472、1615、1451、1551；这些过期提交涉及的请求按期成功数全部为 0。目标 OBU 在期限后才完整收到的 Data 也没有计入成功。

这说明此前找到的 VTDF 过期等待/额外提交问题确实浪费资源，但 **F01 已排除迟到成功**，不能再次从成功数里扣除这些请求。F05 的过期额外提交归因不能用来人为“校正”F01 柱高。

源码中的待转发条目缺少原始请求期限，`found` 到来可刷出过期 Data，超时路径又没有完整覆盖不同缓存；原请求基站的等待队列与其他中继等待队列也有不同本地重关联释放行为。详见原[Circle VTDF 诊断](圆圈场景VTDF诊断_20261023.md)。修复必须保留真正的原期限，不能从入队时间重新给 3 秒，也不能读取实验 recorder 的全局真值来替代协议状态。

## 下一步按问题分开处理

本轮未启动以下修复或新实验。后续实施应保持现有图和批次，另建版本与结果目录。

1. **共享关联正确性**：先测试“超过 2 秒无 hello、恰好到期、重新收到 hello、切换到新 RSU、Stop 清理”等真实回调，再补发送前检查或独立清理。四策略使用相同的基础修复，并新增 hello 实际接收时间、选择 RSU/MAC、条目年龄记录。验收目标是不会继续使用已过期邻居，不承诺消除物理盲区。
2. **Spider 的研究场景设计**：若目标是研究覆盖内切换后的回程补救，检查 RSU 布设、轨迹、功率/灵敏度和传播模型是否形成合理的连续覆盖与交叠；预先固定新配置，对四策略统一使用。先做几何与短跑验收，再考虑全批。保留当前带盲区结果，不能只删除失败车辆或把新配置的有利点塞进旧曲线。
3. **Circle/Grid 的末段交付**：先对固定条件和种子补最小旁路记录，把请求、选定站、MAC 目的地址、排队/丢弃、分片接收关联起来，验证观察开关不改变行为。Circle 优先复核 9000/12000 两档，Grid 补低/高负载对照；定位后再尝试有明确触发条件的队列或转发改动。
4. **VTDF 生命周期**：单独补“过期 found、本地重新登记、重复 found、结束清理”的回归，修复有效期/释放/去重；随后保留旧新 VTDF 与固定 TKAN-PDF 的配对小批量对照。VTDF 修复可能提升性能，应保留真实结果。
5. **比较验收**：共享修复需检查四策略；神经专用改动需明确适用范围。每次先检查功能与计数，再报告 ISR/RTT/负载变化，不能只用是否超过 VTDF 决定一次实验是否有效。不因结果不利而删种子或改柱高。
