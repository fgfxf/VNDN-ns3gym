# Period准确率统计口径复核（2026-11-17）

本次只读取已有20/200/1000/2000 ms、三场景×三种子共36轮记录，没有重跑仿真、训练或推理。没有替换`问题.md`的表格、原图集数据或绘图脚本。以下准确率均先按种子计算，再平均84001/84002/84003三个种子；样本数为三个种子合计。

## 结论

现有记录不能支持“整体预测准确率约99%→95%→92%→89%”这一指定曲线。共同匹配口径排除了大量困难样本，对说明hello机制的必要性不合适；上一轮只报告其高准确率而未同时检查返回时迁移比例，解释不充分。

更贴近研究目标的已有指标是“返回时跨RSU迁移请求的Top-1预测准确率”：它显示明显的下降，但起点远低于99%，蜘蛛网末档也不是严格单调。固定6000请求分母的正确预测覆盖率，在圆圈和方阵下降，在蜘蛛网上升，不能声称三场景均得到期望结论。

## 为什么共同匹配准确率接近100%

| 场景 | 四档共同匹配样本数 | 其中返回时服务RSU不同于源RSU的样本数 |
| --- | ---: | ---: |
| 圆圈 | 16444 | 0 |
| 方阵 | 14170 | 8 |
| 蜘蛛网 | 8187 | 0 |

圆圈、蜘蛛网的共同匹配集合中，“永远预测源RSU”即可获得100%准确率。蜘蛛网模型在此集合的97.09%→95.59%，并不说明模型具有约97%的跨站预测能力。四档交集要求样本每档均可评价、源RSU相同、真实标签相同，形成了对稳定驻留样本的强烈选择。

以20 ms蜘蛛网为例，原全样本共12845条；共同匹配保留8187条，另4658条被排除。保留部分准确率为97.09%，排除部分准确率按种子均值仅57.30%。这说明原83.21%变为97.09%主要涉及样本组成变化，不能把两者当作同一总体的改进。

## 当前真实标签也受hello影响

现有标签由[formal_data.py](../../contrib/vndn-nn-rd/ai-training/formal_data.py)读取mobility-events.csv中Router回程时刻的服务RSU。关联日志来自[VndnObu::OnSyncSignalInterest](../../contrib/vndn-nn-rd/apps/vndn-obu.cc)收到hello后的驻留选择与超时清理，不是独立于hello的物理位置最优站标签。RSU超时还随周期按2T变化。

原全样本中，蜘蛛网“真实标签等于源RSU”的比例从81.79%升至96.20%、98.65%、98.95%。因此较长周期不仅让输入更旧，还改变了关联/切换过程和被预测的标签，使简单的原站预测更容易“正确”。这能解释为什么当前总体准确率可能反而上升，但尚未把无线丢失、切换抖动等因素的贡献逐一隔离。

另作诊断：在四档共同请求和源RSU上，固定20 ms标签作为参考，蜘蛛网预测与参考标签的一致率为87.47%→87.12%→86.56%→85.74%。参考标签不是其他运行的独立真值，因此这里只称“一致率”，不改名为Accuracy，也不能达到期望的大幅下降。

## 为什么50%左右的兴趣满足率不直接否定高预测准确率

离线预测准确率只要求可评价样本中预测服务RSU正确；即使无线Data最终没有到达车辆，也可能得到正确的RSU标签。兴趣满足率要求请求在截止前收到Data，还受到覆盖、上行、回程、拥塞和无线末段交付影响。两者事件和分母不同，不能相互替换；不同批次/参数的数值更不能直接比较。本36轮是NoForward采样离线评估，不能从中虚构TKAN-PDF在线四周期满足率。

## 对后续论文指标的建议

若只用现有记录，可以同时给出“全有效样本Top-1准确率”“返回时跨站预测准确率（附样本数）”“正确预测覆盖率”，并明确探索性口径及结果不完全单调。不能选择某个种子、按预测正确性筛样本、逐档更换条件或把缺少真值的请求直接改成错例，来凑指定的99/95/92/89。

若要严格验证hello新鲜度对预测的作用，需要在同一请求、同一目标时刻和独立于hello的目标定义下控制历史更新频率；或以固定20 ms轨迹/标签为参考离线降采样输入，再重新推理。后者不需要重跑仿真，但需要新的推理，且是新的离线实验；本次没有执行。若论点是hello是否提升实际交付，则还需在线有/无hello或周期对照，单靠当前条件准确率不能完成证明。
