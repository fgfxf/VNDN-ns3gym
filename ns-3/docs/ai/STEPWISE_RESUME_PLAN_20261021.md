# 分步骤执行与中断恢复方案

日期：2026-10-21（Asia/Shanghai）。状态：**需求已确认；本文件是实施计划，功能尚未实现或验收。**

用户担心长流水线因进程关闭、终端退出或电脑关机丢失工作。本方案保留既有实验设计、采集器和
训练方法，把执行改成用户手动选择步骤、每次限制工作量、完成结果独立保存并可核验复用。
当前全部实验队列继续停止。本轮只更新文档，不修改实现、不configure、不编译、不运行实验或训练。

## 1. 已确认的四项选择

1. 仿真以完整一轮为恢复单位：已完成并校验的轮次复用，中断所在轮从头重跑；不恢复ns-3/SUMO运行内存。
2. 用户手动选择采样、整理数据、训练、评估、正式实验、出图；允许限定本次最多运行几轮，完成后退出。
3. 训练每个完整epoch保存恢复状态；已完成的初始化候选模型跳过，中断候选从最近有效提交继续。
4. **只保留立即停止**：不实现“本轮结束后暂停”，不等待当前仿真或epoch跑完。

正式规模仍由用户另行选择：旧17条件/918采样/4080正式，或新8条件/48～72采样/480正式。
本方案从设计清单读取作业，不硬编码轮数，不因恢复机制调整条件、种子、模型选择规则或统计口径。
参见[精简计划](SLOWDOWN_AND_REDUCED_EXPERIMENT_PLAN_20261021.md)与[旧参数计时](OLD_DESIGN_TIMING_20261021.md)。

## 2. 六个手动步骤

| 步骤 | 用户选择 | 独立保存单位 | 再次执行同一步时的处理 |
|---|---|---|---|
| 采样 | split、场景、条件、种子、本次最多轮数 | 一轮NoForward仿真 | 核验并跳过完整轮，只重跑中断轮 |
| 整理数据与覆盖检查 | 场景 | 一个场景的数据集及覆盖报告 | 复用完成的数据集；未完成时重建该数据集，不重采原始数据 |
| 训练 | 场景 | 初始化候选及每个epoch | 完成候选跳过；当前候选从最后提交的epoch继续 |
| 冻结与独立评估 | 明确冻结三场景模型，再选择评估场景 | 冻结清单、每场景评估报告 | 模型不重选；完成评估复用，未完成评估重跑 |
| 正式实验 | 场景、条件、配对种子、本次最多轮数 | 一种算法的一轮仿真 | 完成轮跳过，只补缺失轮；同条件四算法仍保持配对 |
| 汇总与出图 | 已冻结批次 | 汇总与图集 | 完成产物复用；失败时重新汇总/绘图，不重复仿真 |

每条命令只执行用户指定步骤，不自动补跑其前置步骤，也不接着运行下一步骤。
前置条件不足时，显示具体缺项及对应命令。正式实验仍要求三个固定模型和独立评估齐备。
数据集继续按原契约要求训练/验证/独立评估三个split完整、种子隔离；不将不完整采样静默送入训练。

建议新增统一轻量入口`tools/experiments/run_campaign_step.py`，调用既有`campaign.py`与
`campaign_workflow.py`，不另造一套作业执行引擎。操作语义拟定如下，**这些新命令尚未实现**：

| 动作 | 拟定语义 |
|---|---|
| `sample --split train --scene circle --max-jobs 4` | 本次最多新执行4轮；复用的完成轮不占配额 |
| `datasets --scene circle` | 只构建/核验圆圈数据集并检查覆盖 |
| `train --scene circle` | 只训练或续训圆圈，按原先声明的初始化种子依次进行 |
| `freeze-models` | 核验三场景选定模型，独立提交冻结清单 |
| `evaluate --scene circle` | 只评估冻结的圆圈模型 |
| `formal --scene grid --max-jobs 4` | 本次最多新执行4轮正式仿真，完成后退出 |
| `figures` | 对完整正式矩阵汇总出图；不自动启动缺失实验 |
| `status --watch` | 只读查看阶段、轮次、候选/epoch和累计进度 |
| `stop` | 立即终止本批次自有进程，保留数据；不启动下一项 |
| `recover --check` | 只核验并报告可恢复/缺失/损坏项；不运行仿真或训练 |

全部动作显式指定同一个`--root`。再次手动执行同一工作命令就是继续，不要求用户手工修改进度文件。
默认前台显示进度；环境已有tmux，可用于终端断开后继续当前步骤。电脑关机后不自动开跑，
由用户再次执行相同步骤。终端保活不能替代磁盘上的恢复记录。

## 3. 已有能力与真实缺口

- `campaign.py::completed_attempt/reconcile_attempts`已有完成轮校验复用、磁盘attempt与状态对账。
  `run`已支持`--split/--scene/--condition/--seed/--max-jobs`；无需重新设计独立仿真轮的概念。
- `campaign_workflow.py::_stage`已有完整场景阶段复用和失败attempt保留，但训练中断后会重新训练
  当前场景全部初始化种子；数据集和评估也按当前场景重做，出图按整个阶段重做。
- `formal_training.py`每epoch写日志，仅验证指标改善时保存推理权重；现有文件没有Adam、随机状态、
  当前epoch与早停计数。重开使用新时间戳目录，没有真正的epoch续训入口。
- `campaign.py`默认历史总attempt上限为2，人为中断也计入。重复关机可能导致下次直接拒绝继续。
- 输入文件逐个写进最终目录；关机可能留下半生成目录，后续因目录已存在而无法正常生成。
- 部分JSON虽使用临时文件再替换，但没有文件及父目录的持久化提交；训练权重直接覆盖。
  主状态损坏时缺少统一的核验、隔离和重建入口。
- 源码总哈希包含实验工具和训练代码：修改恢复功能会改变原冻结身份，需要显式处理旧数据兼容。
- no-build运行已有二进制/依赖前后核验，但只约束同一轮，不保证多轮跨重启使用同一运行环境。

## 4. 仿真存档与恢复

### 4.1 完成的判据

一轮的身份包含场景、条件、策略、完整随机种子元组、测量窗口、输入契约及模型身份。
一次重试仍是同一轮的新attempt，不算新的独立重复。

保持现有`manifest.json`与原始数据校验，在其上明确持久化完成边界：

1. 仿真成功退出，确认原始完成标记、请求闭合、车辆活动区间和必要文件齐备。
2. 校验输入、源码/运行环境、模型及产物哈希；对子进程已经关闭的必要结果文件执行持久化写入。
3. 保存可独立核验的完成记录：临时文件→flush/fsync→同文件系统原子替换→父目录fsync。
4. 完成记录提交后才增加“已完成”计数，才能启动下一轮。

进度JSON是可重建索引，不能成为唯一事实。每轮记录及原始产物才是恢复依据。
持久化只在每轮/阶段提交边界进行；心跳仅轻量更新显示，不每几秒刷写全部原始文件。

### 4.2 再次启动

- 先取得当前批次与仿真端口的既有锁，核查上次进程身份。若遗留子进程仍活着，说明情况并支持`stop`清理，
  不并发启动另一轮，也不按程序名批量杀掉用户进程。进程身份记录增加系统启动标识以区分重启前后。
- 状态显示未完成但产物完整：完整核验后补登记，不重跑；不能只看文件名或退出码。
- 状态显示完成但文件缺失/损坏：报告具体文件并隔离为待处理，不将其计为有效结果。
- 未完成的原始文件保留在原attempt；下一次另建attempt从头执行，绝不拼接两次仿真的CSV。
- 状态索引损坏时保存原文件，按有效完成记录与attempt重建；不能恢复的项目保留诊断原因。
- 输入先在临时目录生成，检查完整且发布后路径有效，再原子提交。旧半目录仅在未封存、未被完整轮引用时隔离重建。

人为停止、已确认的重启中断与程序错误分别记录。手动恢复不因过去已有两次中断而永久拒绝；
保留完整attempt历史，真正的运行错误默认停下报告，不无限自动重试。

## 5. 训练恢复

实现集中在三个场景共用的`contrib/vndn-nn-rd/ai-training/formal_training.py`。
继续使用现有TKAN-LSTM、Adam、归一化、类别权重、验证集选择规则和三个初始化种子；不更改科学方法。

### 5.1 稳定的恢复身份

训练工作目录由批次、场景、数据集和训练配置身份确定，各初始化种子独立子目录。
workflow的attempt仍另存命令与日志，但重新开一个attempt不应重新创建全部训练进度。
恢复前核验数据、模型结构、超参数、初始化种子列表及顺序、设备/依赖环境。
不匹配时解释差异并停止，不能静默覆盖或当成同一次训练。

### 5.2 保存内容与时机

每个候选初始化完成时提交epoch 0；每个完整epoch完成训练和验证后，提交一个一致的恢复包：

- 当前模型权重、Adam状态、当前epoch及累计训练历史；
- 截至该epoch的最佳权重、最佳指标、对应epoch及早停计数/终止原因；
- Python、NumPy、Torch CPU/CUDA随机状态，以及训练DataLoader的generator状态；
- 数据集、训练配置、初始化种子和训练实现身份。

当前权重用于继续优化，最佳权重用于最后导出推理模型，二者不能混用。
最佳权重必须独立复制，不能保留会随继续训练变化的张量引用。

恢复包先写新文件并fsync，再原子提交包含路径和哈希的小记录；保留前一份有效提交用于故障排查。
`history.jsonl`等展示文件可由已提交包重建，避免日志多写一行便跳过一个epoch。
未被完成记录引用的临时文件不算进度。最新已提交包若校验失败，明确报告，不静默宣称正常恢复。

### 5.3 恢复顺序与停止

先构造并加载模型、优化器及DataLoader，最后恢复随机状态，紧接下一次训练迭代；
不能为展示进度额外取batch或跑验证而改变随机序列。
已达到最大epoch或触发早停的候选，只补导出和登记，不清零早停计数继续训练。
完成候选验证后跳过，所有候选齐备后仍按原验证指标规则选择最终模型。

收到`stop`或Ctrl+C后立即终止，不额外等本epoch完成；中断所在epoch从最近完整提交重算。
默认验收当前CPU单线程路径，不能未经测试承诺跨设备或不同库版本逐位一致。

## 6. 旧数据兼容与版本边界

这是实施前必须处理的真实问题：仅修改`tools/experiments`或训练文件也会改变总源码哈希。
只放宽`campaign.py`的一处检查并不足够，`formal_data.py`、workflow和模型契约也有一致性检查。

采用**一次受限、可审计的工具版本迁移**，不直接重写旧run、旧manifest或旧冻结设计：

1. 修改前封存现有代码/配置及运行环境，完整核验待继承的结果。
2. 新执行版本使用新的批次记录；兼容清单逐一列出被继承的旧run路径、manifest/产物哈希、
   原源码身份、split/条件/种子及新作业的对应关系，不以一个宽泛的“忽略版本”开关接纳任意数据。
3. 审查原/新代码的完整差异，仅允许已测试的执行、持久化和续训机制变化；
   仿真C++、调度器修复、路网/请求生成语义、采集字段/标签和统计定义必须保持一致。
4. campaign、export、数据集构建和workflow共用该兼容证明并保留逐run真实来源；
   新数据集/模型记录兼容清单哈希及来源清单，不能伪装所有旧run均由新源码生成。
   以显式版本区分当前执行源码、每个shard的实际采集源码和训练代码身份，不静默改变旧
   `source_code_sha256`的含义。普通无迁移记录的旧流程仍维持严格单一源码规则。
5. validation_only、种子隔离、场景/标签契约和完整性检查不得放宽；同一run不得重复导入或跨split使用。
6. 新执行版本封存运行二进制、相关动态库和运行依赖。旧run若使用不同二进制，默认不自动接纳，
   列明构建差异及所需受控同输入验证，核验通过前保持隔离；无法说明的变化保留该结果及原因供后续处理。
   旧run未记录的SUMO/Python环境不得由当前环境追认为一致，迁移时补封存只说明当前版本。

现有数据的处理：

| 数据 | 已核查状态 | 用途 |
|---|---|---|
| `retrain-compact-20261021` | 1轮完整采样（circle、baseline、seed21001），另1轮中断 | 原设计不变时可复用；工具升级后须经过上述兼容接纳 |
| `old-design-timing-20261021` | 3轮完整10车计时，均validation_only；第4轮中断 | 保留计时/工程验证证据，不改成正式训练或论文正式重复 |
| 原`retrain-20261021` | 历史慢运行没有完整通过的pilot | 原始证据保留，不作为完整采样结果 |

已核对：compact完整轮记录的NDN库SHA256为`61ba9d363b84e06e3cfbe4aa46ba97c7328843ca73bdcf04612a44285002fac9`，
当前库为`03340d2e13cf968dd2faba9c2b24cc2a3138e3267272ccfb3b9674dbea129f7c`；二者不同。
源码身份仍匹配不等于这项运行时差异已经解释。因此当前不承诺这1轮在更严格的新运行环境契约下
可无条件混入新批次；数据保持原样，兼容检查须列出差异和处理证据，不为迁移重新编译或改写旧哈希。

若用户最后选择不同规模或种子设计，按新设计审查每项资格；不能把seed21001改写成另一seed来凑数。
“不白费”指兼容且完整的结果不重复计算，不能将中断或不符合统计设计的记录冒充正式样本。

## 8. 测试先行与交付次序

先建立现有相关Python测试基线；逐项添加会在旧实现失败的行为测试，修复后通过再推进。
不能把测试构造/导入错误当行为红灯，不能为恢复成功而跳过数据校验。

| 次序 | 实施项 | 必须验证的行为 |
|---|---|---|
| 1 | 旧证据盘点与受限兼容 | 旧manifest字节不变；正确完成轮可复用；篡改、错seed、跨split、validation_only混入均拒绝 |
| 2 | 仿真与输入恢复 | complete但索引未更新可补登记；中断只重跑本轮；主索引损坏可重建；半输入目录不会误用 |
| 3 | 手动阶段与立即停止 | 限额只计新执行轮；阶段完成不启动下一步；立即停止清理自有子树；不触碰其他手动进程 |
| 4 | 训练恢复 | 连续与中断续训的当前/最佳权重、Adam、history、早停位置、选中候选一致；完成候选不重训 |
| 5 | 故障注入 | 文件写入中、原子提交前后、候选导出中、种子初始化前后中断，均只认有效提交 |
| 6 | 小规模整体验收及文档 | 分批执行→立即停止→相同命令恢复→训练/评估/出图，不重复计数且所有原始证据保留 |

训练一致性测试使用shuffle和非零dropout，覆盖RNG；包含早停已触发但完成标记未落盘的边界。
模拟主进程SIGKILL并检查子进程、锁和恢复，不真的关闭用户电脑。
fsync/原子发布的故障注入验证提交顺序，不能把它说成实际断电或硬盘损坏实验已经通过。
