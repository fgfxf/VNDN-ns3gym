## 周期与记录的含义

`hello_interval_ms`控制RSU发送hello以及检查车辆失联的周期；默认仍20毫秒。
RSU失联判定是距最后一次接收车辆hello响应的时间**严格大于2T**，并在每个T的周期检查。
四档阈值为40/80/160/320毫秒；它不是保证精确在这一毫秒离线，检查相位会影响发现时刻。
OBU原有2000毫秒邻站失效规则和业务3秒超时不改。

这次评价固定模型对整套信标周期配置的适应性，包含关联时序变化；不是每档重新训练后的最优效果。
模型始终输入10×6，名义历史跨度为9T，真实时间戳以快照为准。

旁路`rsu-state.csv`记录真实容器条目数及变化时间，包含历史遗留的实际条目，不清理容器来缩小统计值。
`hello-payloads.csv`记录实际编码内容字节和完整NDN包字节，并区分注册、增量、空增量等情况。
前者不是C++堆内存，后者是应用构造的包，不能直接当作无线实际发射数量。
原网络/控制负载仍来自网络Face的L3出站记录，原额外Data指标仍是应用显式提交次数。

神经方案保留已有VNH1/CBOR编码及空增量省略，其他策略维持已有JSON。该差异仅在本方法说明中记录，
不向对比HTML/图增加额外优化标注；不能将整个方案的通信收益全部归因于模型预测准确率。
已知VTDF过期等待队列问题本次不修复，旧264轮的探索性质、成功RTT选择效应等限制保留。

## 日常操作

所有命令在项目主目录执行，默认使用本次独立批次目录。

持续看进度（每5秒更新一次）：

```bash
cd /home/fgfxf/ndnSIM/ns-3
python3.8 tools/experiments/followup_campaign.py status --watch
```

只看一次可去掉`--watch`。按Ctrl+C只退出查看窗口，不会停止后台实验。
显示完整99轮完成/剩余、36/36/27各模块进度、当前场景/策略/周期/车数/种子、当前轮和本次/累计用时；不估算剩余时间。
出图阶段继续显示当前分析或图片名称，不再只是一个长时间不变的figures标记。

需要马上停止本批次时：

```bash
python3.8 tools/experiments/followup_campaign.py stop
```

该命令核对PID与启动身份，仅停止本批次及其子仿真/控制器。突然断电与立即停止不恢复半轮内存；已完成且校验通过的轮次保留。
重新开机后继续，或手动启动尚未开始的批次：

```bash
cd /home/fgfxf/ndnSIM/ns-3
export JOBS=4
python3.8 tools/experiments/followup_campaign.py resume
```

手动命令在前台运行；本次由AI用脱离终端的后台进程启动，关闭查看终端不影响实验，但电脑关机后要重新运行resume。
可附`--max-runs 3`限制本次新增完整仿真轮数。正常连续完成99轮后自动分析和出图。
单任务最多保留两个attempt；连续失败后停止并保留证据，不无限重试，不因指标不好删轮。
